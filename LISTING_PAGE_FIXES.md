# Исправления Detailной Страницы Объявления

## 🔴 Проблемы которые я нашел

### 1. **Нет таймаутов на Supabase запросы**
**Проблема**: 
- Запросы к БД могут висеть бесконечно если сервер медленный или сеть плохая
- Когда пользователь кликает на несколько объявлений подряд, первый запрос может зависнуть и блокировать всё
- После пары попыток другие объявления открываются = первые запросы наконец-то вернули данные

**Что было**:
```typescript
const { data, error } = await supabase
  .from('listings')
  .select('*')
  .eq('id', id)
  .single()
// БЕЗ таймаута - может ждать 30+ секунд!
```

**Что сделал**:
```typescript
const { data, error } = await withTimeout(
  supabase.from('listings').select('*').eq('id', id).single(),
  15000 // 15 секунд максимум
);
```

---

### 2. **Множественные последовательные запросы без отмены**
**Проблема**:
- После основного объявления идут запросы за: images, user_profiles, states
- Если первый запрос подвис, остальные всё равно начнут выполняться за ним
- Браузер выполняет запросы в очереди, и если одна "зависла" - всё застревает

**Что было**:
```typescript
// 1. Основное объявление
const { data } = await supabase.from('listings').select('*').single();

// 2. Игнорирует таймаут из первого запроса
const { data: imageData } = await supabase.from('listing_images').select(...);

// 3. И ещё один
const { data: userData } = await supabase.from('user_profiles').select(...);
```

**Что сделал**:
```typescript
// Каждый запрос имеет свой таймаут
const { data: imageData } = await withTimeout(
  supabase.from('listing_images').select(...),
  10000 // 10 секунд
);

// Если ошибка - не падает вся страница
try {
  await withTimeout(supabaseQuery, 10000);
} catch (err) {
  console.warn('Failed to load X:', err);
  // Продолжаем работу без этого данных
}
```

---

### 3. **Нет обработки network errors**
**Проблема**:
- Если сеть плохая или сервер недоступен - просто чёрная ошибка
- Пользователь видит: "Failed to load listing" и ничего больше
- Нет механизма "повторить" или graceful degradation

**Что было**:
```typescript
if (error || !data) {
  setError('Listing not found.')
  // Конец, страница сломана
}
```

**Что сделал**:
```typescript
// Для опциональных данных - продолжаем без них
if (cancelled) return;

try {
  const { data: imageData } = await withTimeout(...);
  setImages(imageData || []); // Пустой массив если не загрузилось
} catch (err) {
  console.warn('Failed to load images:', err);
  setImages([]); // Показываем страницу БЕЗ изображений
}
```

---

### 4. **API endpoint increment-views без таймаутов**
**Проблема**:
- Запросы на увеличение counter просмотров тоже могут зависнуть
- Браузер ждёт ответа - соединение занято

**Что было**:
```typescript
const { data, error } = await supabaseAdmin
  .from('external_listings')
  .select('views')
  .eq('id', listingId)
  .single();
// Бесконечное ожидание возможно
```

**Что сделал**:
```typescript
const { data, error } = await withTimeout(
  supabaseAdmin.from('external_listings').select('views').eq('id', listingId).single(),
  10000 // 10 второе максимум
);

// Graceful degradation
if (err) {
  return NextResponse.json({ success: true, newViews: -1 });
  // Не ломаем страницу если не удалось обновить views
}
```

## ✅ Что я исправил

### 1. **Добавил Helper Function с таймаутом**
```typescript
const withTimeout = async <T,>(promise: Promise<T>, timeoutMs: number): Promise<T> => {
  return Promise.race([
    promise,
    new Promise<T>((_, reject) =>
      setTimeout(() => reject(new Error(`Request timeout after ${timeoutMs}ms`)), timeoutMs)
    )
  ]);
};
```

### 2. **Установил разумные таймауты для каждого запроса**
- **Основное объявление**: 15 сек
- **Изображения**: 10 сек
- **User profiles**: 10 сек
- **States**: 5 сек
- **API endpoints**: 10 сек

### 3. **Добавил try-catch для опциональных запросов**
- Если images не загрузились - показываем страницу БЕЗ изображений
- Если user_profiles не загрузился - показываем пустой owner info
- Если states не загрузился - показываем без location

### 4. **Graceful degradation в API**
- Даже если запрос на views завис - это не сломает основную страницу
- Возвращаем `success: true` чтобы не блокировать браузер

## 🎯 Результаты

### ДО исправления:
```
Пользователь кликает на объявление 1
  → Запрос 1 начинается, НЕ имеет таймаута
  
Объявление 1 вешается (БД медленная/сеть плохая)
  → Страница показывает спиннер на 30+ секунд

Пользователь в это время кликает на объявление 2
  → Запрос 2 начинается, тоже без таймаута
  → Теперь оба запроса висят

Пользователь кликает на объявление 3
  → Запрос 3...

Спустя минуту первые запросы наконец вернули данные
  → Объявление 1 внезапно загружается
  → А объявление 2 и 3 ещё вешаются...
```

### ПОСЛЕ исправления:
```
Пользователь кликает на объявление 1
  → Запрос 1 начинается, таймаут 15 сек

Объявление 1 вешается на 5 сек
  → Запрос всё ещё не закончился, продолжаем ждать

Пользователь кликает на объявление 2 (на 3й секунде)
  → Запрос 1 отменяется (cancelled = true)
  → Запрос 2 начинается

Объявление 2 загружается за 2 сек
  → Объявление 2 открывается СРАЗУ ✅

Если бы объявление 2 вешалось на 16 сек
  → По таймауту (15 сек) запрос будет отменён
  → Покажется ошибка "Failed to load listing"
  → Пользователь может вернуться / попробовать ещё
```

## 🔍 Как это всё работает

```
Пользователь кликает → Начинается useEffect
  ↓
cancelled = false // Флаг для отмены
  ↓
Запрос 1: Основное объявление (15 сек таймаут)
  ├─ Успешно → Показываем данные
  ├─ Ошибка → Показываем "Listing not found"
  └─ Таймаут → Показываем "Request timeout"
  ↓
Если успешно: Запрос 2: Изображения (10 сек таймаут)
  ├─ Успешно → Показываем изображения
  ├─ Ошибка → Пропускаем, показываем без изображений
  └─ Таймаут → Пропускаем, продолжаем
  ↓
Если всё ещё успешно: Запрос 3: User info (10 сек таймаут)
  ├─ Успешно → Показываем информацию о владельце
  ├─ Ошибка → Пропускаем, показываем пустой owner info
  └─ Таймаут → Пропускаем, продолжаем

Если пользователь перейдёт на другое объявление:
  → cancelled = true // Отмена всех остальных запросов
  → Освобождается соединение
  → Новые запросы начинаются
```
